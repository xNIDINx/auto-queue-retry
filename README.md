# Auto Queue Retry — Автопоиск боя

Мод для «Мира танков», который повторяет поиск одиночного случайного боя на выбранной в ангаре технике. Время ожидания, пауза между попытками, горячая клавиша и лимит перезапусков настраиваются прямо в игре.

Текущая версия: **1.3.0**. Проверялась на клиенте **1.44.0.0**. Совместимость с последующими обновлениями клиента требует отдельной проверки.

## Скачать и установить

1. Скачайте [local.auto_queue_retry_1.3.0.mtmod](https://github.com/xNIDINx/auto-queue-retry/raw/refs/heads/main/dist/local.auto_queue_retry_1.3.0.mtmod).
2. Закройте игру и скопируйте `.mtmod` в `<папка игры>/mods/<текущая версия клиента>/`. Распаковывать файл не нужно. Для проверенной версии клиента путь оканчивается на `mods/1.44.0.0/`.
3. Оставьте в папке только одну активную версию Auto Queue Retry: старую перенесите в резервную папку или переименуйте, добавив `.disabled`.
4. Для настроек в ангаре установите [ModsSettingsAPI](https://github.com/izeberg/modssettingsapi) и его зависимость [ModsListAPI](https://gitlab.com/poliroid/modslistapi). Мод проверялся с `izeberg.modssettingsapi_1.7.0.mtmod` и `me.poliroid.modslistapi_1.6.01.mtmod`.
5. Запустите игру.

Внешние библиотеки и исходники клиента в репозиторий не включены.

## Как пользоваться

Выберите танк в ангаре и режим одиночного случайного боя. Нажмите **F8** — мод начнёт поиск. Если бой не найден за настроенное время, он запросит выход из очереди, дождётся подтверждения выхода, выдержит паузу и снова нажмёт «В бой».

Повторное нажатие горячей клавиши останавливает цикл и запрашивает выход из очереди. Когда бой найден, автопоиск завершается сам. После боя новый цикл запускается вручную. Мод не управляет танком в бою.

При лимите **20 перезапусков** мод может отменить поиск 20 раз. После этого он входит в очередь в 21-й раз и ждёт бой без тайм-аута отмены. Горячая клавиша ручной отмены продолжает работать. Каждый новый запуск цикла обнуляет счётчик.

## Настройки в ангаре

Откройте **Модификации → Настройки модификаций → Автопоиск боя**.

| Настройка | По умолчанию | Диапазон и шаг |
| --- | --- | --- |
| Мод включён | Да | Включить / выключить |
| Время ожидания в очереди | 15 сек. | 5–60 сек., шаг 1 сек. |
| Пауза перед повторным поиском | 2 сек. | 1–15 сек., шаг 0,5 сек. |
| Горячая клавиша запуска и отмены | F8 | Назначается через ModsSettingsAPI |
| Максимальное число перезапусков | 20 | 5–100, шаг 5 |

ModsSettingsAPI сохраняет значения между запусками игры. Пауза отсчитывается от подтверждения выхода из очереди. Настроенное время ожидания приблизительно соответствует видимому таймеру: мод отсчитывает его от события входа в очередь с поправкой +2 секунды, а не считывает цифры с экрана. Время анимации, задержки клиента и сервера могут влиять на совпадение.

При недоступной кнопке «В бой», отказе сервера или исключении из очереди цикл останавливается. Если назначенная клавиша занята другим модом, выберите другую в настройках.

## Исходный код и сборка

- [mod_auto_queue_retry.py](src/res/scripts/client/gui/mods/mod_auto_queue_retry.py) — логика очереди и интеграция настроек.
- [meta.xml](src/meta.xml) — идентификатор и версия пакета.
- [build.py](build.py) — сборка `.mtmod` без сторонних Python-библиотек.
- [CHANGELOG.md](CHANGELOG.md) — история версий.
- `dist/` — готовый пакет.

Для сборки нужен **Python 2.7**: клиент использует его байткод. Пример команды в PowerShell из корня репозитория:

```powershell
& 'C:\Python27\python.exe' build.py
```

Скрипт прочитает версию из `src/meta.xml`, скомпилирует модуль и создаст `dist/local.auto_queue_retry_1.3.0.mtmod`. Архив содержит только `meta.xml` и `.pyc`; все записи сохраняются без сжатия (`ZIP_STORED`). В байткод записывается относительный путь, поэтому путь к локальной папке разработчика не попадает в пакет. Сборка не устанавливает мод в игру.

Сам мод запускается внутри клиента игры: `BigWorld`, `Keys` и остальные клиентские модули не являются зависимостями из PyPI.
