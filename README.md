# Поиск генерального сражения

**Автор: nidin.** Мод для «Мира танков», предназначенный для поиска **«Генерального сражения»** через короткие повторные входы в очередь случайных боёв.

По наблюдениям автора, при включённой галочке «Генеральное сражение» первые примерно **15–20 секунд** поиска отводятся преимущественно подбору этого типа боя. Отмена затянувшегося поиска и новый вход позволяют повторять этот начальный этап. Мод автоматизирует такие попытки на выбранной в ангаре технике.

Перед запуском **включите «Генеральное сражение» в настройках игры** и выберите подходящую для него технику. Мод сам галочку не включает. Попадание в ГС не гарантируется: тип найденного боя определяет сервер, а интервал 15–20 секунд описывает наблюдение автора, а не фиксированное правило балансировщика.

Текущая версия: **1.3.1**. Идентификатор пакета: `nidin.auto_queue_retry`. Предыдущая версия 1.3.0 проверялась на клиенте **1.44.0.0**; совместимость с последующими обновлениями клиента требует отдельной проверки.

## Скачать и установить

1. Скачайте [nidin.auto_queue_retry_1.3.1.mtmod](https://github.com/xNIDINx/auto-queue-retry/raw/refs/heads/main/dist/nidin.auto_queue_retry_1.3.1.mtmod).
2. Закройте игру и скопируйте `.mtmod` в `<папка игры>/mods/<текущая версия клиента>/`. Распаковывать файл не нужно. Для проверенной версии клиента путь оканчивается на `mods/1.44.0.0/`.
3. Оставьте в папке только одну активную версию мода. Предыдущий пакет `local.auto_queue_retry_*.mtmod` или более ранний `nidin.auto_queue_retry_*.mtmod` перенесите в резервную папку либо переименуйте, добавив `.disabled`. Настройки прежнего идентификатора переносятся при первом запуске новой версии.
4. Установите [ModsSettingsAPI](https://github.com/izeberg/modssettingsapi) и его зависимость [ModsListAPI](https://gitlab.com/poliroid/modslistapi). Используемая конфигурация: `izeberg.modssettingsapi_1.7.0.mtmod` и `me.poliroid.modslistapi_1.6.01.mtmod`.
5. Запустите игру.

Внешние библиотеки и исходники клиента в репозиторий не включены.

## Как пользоваться

С включённым «Генеральным сражением» выберите подходящий танк в ангаре и режим одиночного случайного боя. Нажмите **F8** — мод начнёт поиск. Если бой не найден за настроенное время, он запросит выход из очереди, дождётся подтверждения выхода, выдержит паузу и снова нажмёт «В бой». Для повторения коротких попыток автор использует время ожидания около 15–20 секунд; точное значение можно подобрать в настройках мода.

Повторное нажатие горячей клавиши останавливает цикл и запрашивает выход из очереди. При нахождении любого боя, в том числе обычного случайного, цикл завершается сам. После боя новый цикл запускается вручную. Мод не управляет танком в бою.

При лимите **20 перезапусков** мод может отменить поиск 20 раз. После этого он входит в очередь в 21-й раз и ждёт бой без тайм-аута отмены. Горячая клавиша ручной отмены продолжает работать. Каждый новый запуск цикла обнуляет счётчик.

## Настройки в ангаре

Откройте **Модификации → Настройки модификаций → Поиск генерального сражения (nidin)**.

| Настройка | По умолчанию | Диапазон и шаг |
| --- | --- | --- |
| Мод включён | Да | Включить / выключить |
| Время ожидания в очереди | 15 сек. | 5–60 сек., шаг 1 сек. |
| Пауза перед повторным поиском | 2 сек. | 1–15 сек., шаг 0,5 сек. |
| Горячая клавиша запуска и отмены | F8 | Назначается через ModsSettingsAPI |
| Максимальное число перезапусков | 20 | 5–100, шаг 5 |

ModsSettingsAPI сохраняет значения между запусками игры. Пауза отсчитывается от подтверждения выхода из очереди. Настроенное время ожидания приблизительно соответствует видимому таймеру: мод отсчитывает его от события входа в очередь с поправкой +2 секунды, а не считывает цифры с экрана. Время анимации, задержки клиента и сервера могут влиять на совпадение.

При недоступной кнопке «В бой», отказе сервера или исключении из очереди цикл останавливается. Если назначенная клавиша занята другим модом, выберите другую в настройках.

## Исходный код и сборка

- [mod_auto_queue_retry.py](src/res/scripts/client/gui/mods/mod_auto_queue_retry.py) — логика очереди и интеграция настроек.
- [meta.xml](src/meta.xml) — идентификатор и версия пакета.
- [build.py](build.py) — сборка `.mtmod` без сторонних Python-библиотек.
- [CHANGELOG.md](CHANGELOG.md) — история версий.
- `dist/` — готовый пакет.

Для сборки нужен **Python 2.7**: клиент использует его байткод. Пример команды в PowerShell из корня репозитория:

```powershell
& 'C:\Python27\python.exe' build.py
```

Скрипт прочитает версию из `src/meta.xml`, скомпилирует модуль и создаст `dist/nidin.auto_queue_retry_1.3.1.mtmod`. Архив содержит только `meta.xml` и `.pyc`; все записи сохраняются без сжатия (`ZIP_STORED`). В байткод записывается относительный путь, поэтому путь к локальной папке разработчика не попадает в пакет. Сборка не устанавливает мод в игру.

Сам мод запускается внутри клиента игры: `BigWorld`, `Keys` и остальные клиентские модули не являются зависимостями из PyPI.

### Проверка переноса настроек

Тесты проверяют перенос настроек прежнего идентификатора, сохранение значений и отсутствие дублирующей строки в меню на методах ModsSettingsAPI 1.7.0. Укажите путь к доверенному пакету API, установленному в игре:

```powershell
& 'C:\Python27\python.exe' tests/test_settings_migration.py --api-package 'C:\Games\Tanki\mods\<версия клиента>\izeberg.modssettingsapi_1.7.0.mtmod'
```

Пакет API в репозиторий не включён. Эти проверки не заменяют проверку работы мода в клиенте игры.
